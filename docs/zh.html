九个域，全部真实实现

不是路线图，不是占位。以下每一项都在仓库里有对应的 Go 代码、API 路由与端到端冒烟断言。

音频解决方案 · 自有 ZAT 协议

不止编排别人的播放终端——Zephyr HiFi Kit 自己就是一条完整音频链路：内核挂载 SMB/CIFS 媒体库、按文件头识别 WAV / FLAC 等格式、服务端 libFLAC 解码，经自有 ZAT 协议（采样时钟 PTS、节点密钥鉴权、授权门禁）推流到终端，ALSA 比特完美出声。终端「正在播放」控制台支持暂停、停止、seek、音量与输出设备切换，并与播放门控联动。真实出声需音频版（CGO）；管理版 ALSA 为占位。

  • SMB/CIFS 内核挂载 + 媒体库扫描入库，凭据不上命令行
  • WAV / FLAC 格式识别，libFLAC 真实解码
  • ZAT 推流：采样时钟 PTS · 节点密钥鉴权 · 授权门禁
  • 终端 ALSA 比特完美输出 + 正在播放控制台

自动更新 · 服务端自升级 + 终端收敛

服务端周期检测发布源最新版本，经 feed SHA256 摘要、可选 GPG 验签与包内 SHA256SUMS 三重校验后原子置换二进制并重启，同时刷新终端分发集。终端 Agent 版本恒跟随服务端：按灰度环逐批下发签名升级命令，下载、校验、dpkg、重启全自动，心跳确认版本后才判定收敛；失败退避重试、达上限挂起可一键重试，播放中的终端自动等待空闲。离线内网把发布源指向镜像即可闭环。

  • 三重校验 + 原子置换，崩溃不留半截二进制
  • 灰度环整环对齐才推进，并行数与重试上限可调
  • 播放保护双侧门禁，升级绝不中断出声
  • 控制台实时状态：检查 · 升级 · 收敛 · 挂起重试

02 · ARCHITECTURE

签名链决定谁能下发

制品从离线签名主机进入仓库，服务端只持公钥信任根，终端只接受通过验签的期望态。

  1. 01

    主密钥离线

    主密钥保存在不联网的介质上，只用于签发子密钥与许可证。它从不进入服务端，也不进入 CI。

  2. 02

    子密钥签名

    构建在离线主机或 CI 完成，签名子密钥对制品出具分离签名。服务端不做在线构建，也不做二进制补丁——那会破坏签名链。

  3. 03

    服务端只持公钥

    服务端导入公钥作为信任根，负责仓库、BOM 期望态、任务编排、席位授权与操作日志。私钥泄露面被压缩到签名主机一处。

  4. 04

    enforce 双门禁

    入库与下发都验签。生产必须 enforce；dev 仅用于本地联调。下发前还要过许可证与终端授权两道门。

  5. 05

    终端受约束执行

    Agent 以 root 运行，但动作被 systemd 单元白名单、ALLOW_POWER / ALLOW_LOCAL 与节点密钥三重约束。播放保护在服务端与终端双侧执行。

一条命令装机，一条命令入网

07 · FAQ

常见问题

服务端必须联网吗？

不需要。主密钥与许可证签发都可以完全离线。服务端只在入库时验签、在下发时把制品推给终端，整个链路可以在隔离 LAN 内闭环运行。终端安装器从服务端 /dl/ 取包，不访问公网。

为什么不做在线构建和二进制补丁？

在线构建要求服务端内置各应用的交叉工具链，体积与攻击面都不可接受；二进制补丁会破坏已签名制品的签名链。两者都被删除，改为「离线/CI 构建 → 签名 → 上传入库」这一条可验证的路径。

播放中的终端会被升级打断吗？

不会。播放门控（FR-3.10）在服务端与终端双侧执行：任务进入 waiting_idle 等待空闲，系统升级、停服务与关机在播放中同样被拦截。服务端返回 409，终端本地控制台也拒绝执行。

许可证是怎么工作的？

服务端内置 3 台终端授权；超出可由私有签发端离线签发许可证扩容，服务端使用签发公钥验签并统计席位占用；终端无需证书。

灰度发布怎么推进？

环的百分比必须合计 100，绑定的 BOM 版本必须已发布。当前环仍有未完成任务时推进一步会返回 409，避免把故障扩散到下一环。删除灰度不会撤销已下发的任务，且支持撤销恢复。

控制台的鉴权在哪里做？

控制台内置单管理员鉴权，首次引导设置管理员名字与密码。管理操作仅允许从服务端本机 localhost 或直连 HTTPS 访问；当前后端不信任反向代理的 TLS 转发头。

误删了 BOM 版本或终端怎么办？

BOM 保留完整版本历史，可回滚到任意已发布版本；回滚会生成一个新的已发布版本而不是覆盖历史。终端注销后支持撤销恢复。破坏性操作在控制台都带撤销入口。

支持哪些终端硬件？

安装器自动识别 amd64、arm64 与 armhf，覆盖 x86 小主机、树莓派 4/5（64 位）与树莓派 2/3（32 位）。管理版 Agent 仅依赖标准库，deb 由内置 debpack 生成，不需要目标机上有构建工具。

音频播放是真实的吗？管理版和音频版有什么区别？

真实。管理版纯 Go（CGO_ENABLED=0），ALSA 输出为占位，适用于无音频硬件的编排场景；音频版经 CGO + libFLAC 解码、终端 ALSA 比特完美出声，走自有 ZAT 协议推流。音频版验证包括 amd64 / arm64 构建、ALSA null 回环与 FLAC 解码往返（断言 PCM 逐比特一致），v0.54 结果以发布自动验证记录为准。两版引擎名、配置与 systemd 单元一致，可互相替换。

媒体库怎么接入？支持哪些音频格式？

Linux 服务端用内核 mount.cifs 挂载 SMB/CIFS 共享（需 cifs-utils），扫描媒体库并按文件头识别音频格式（WAV / FLAC 等），入库为可播放曲目。播放时服务端解码并经 ZAT 推流到已授权终端，终端 ALSA 输出。挂载凭据写入受限文件，绝不出现在命令行或 API 响应里。
